    Справочник API¶

    Символы верхнего уровня, экспортируемые reactifact (см. reactifact/__init__.py). Формат по группам: имя — роль в одну строку. Детали — в док-строках модулей — см. автосгенерированный референс (только на английском, докстринги в коде не переведены): сигнатуры, типы и полный текст докстринга рендерятся прямо из исходников на сайте документации, а не копируются сюда вручную.

    Страницы по областям: Knowledge, Evaluation, Sources, Providers, Recipes, Tracing.

    Стабильность¶

    reactifact всё ещё pre-1.0 (0.25.1), но не rc — поверхность ниже это стабильный контракт, а не движущаяся цель. Он проверяется машиной: tests/test_public_api.py фиксирует reactifact.__all__ и экспорты канонических подмодулей (reactifact.step, reactifact.consume, reactifact.chat, reactifact.tools.use, reactifact.eval, reactifact.recipes, reactifact.providers, reactifact.tracing), поэтому новый экспорт там добавляется осознанно (и документируется), а не случайно.

    • Публичный API = каждое имя в reactifact.__all__ и в запиненных подмодулях выше. Опциональные поверхности reactifact.knowledge, reactifact.viz, reactifact.quick, reactifact.redaction и reactifact.audit документированы и следуют semver, но попадают в freeze-тест по чек-листу 1.0. Если что-то импортируется из reactifact, но не входит в __all__ — это внутренняя деталь без гарантий совместимости. Например, reactifact.relations.RelationGraph и reactifact.commit_log.CommitLog существуют потому, что Context разбили на модули поменьше ради читаемости, но ни один из них не экспортируется: поддерживаемая поверхность — это Context, а не они.
    • SemVer в pre-1.0-стиле: минорный бамп (0.24.0 → 0.25.0) может добавить символы или, в редких случаях, изменить поведение так, что CHANGELOG.md явно пометит это Breaking — минорные релизы до 1.0 всё ещё позволяют reactifact исправить архитектурную ошибку. Патч (0.14.0 → 0.14.1) никогда не убирает и не переименовывает публичный символ и никогда не меняет задокументированное поведение — только чинит баги относительно него.
    • Депрекейшен: символ на пути к удалению остаётся импортируемым и работает минимум один минорный релиз; он помечается deprecated в docstring и в CHANGELOG.md (с заменой) до любого удаления, а удаление происходит только в минорном релизе под заголовком ### Breaking. Если удаление не может ждать, это явно указывается в ### Breaking и в migration-гайде (такое исключение — Effects.ask/resume/act в 0.23).
    • Любое ломающее изменение помечено в CHANGELOG.md заголовком ### Breaking, даже в pre-1.0 релизе — см. release.md. Если перед апгрейдом читать только один раздел — читайте этот.
    • 1.0 означает, что эта страница замирает: критерии релиза — это планка выхода из pre-1.0; после него действует SemVer 1.x (никаких ломающих изменений в миноре).
    • Всё, что находится под reactifact.cli.* за пределами задокументированных подкоманд python -m reactifact …, а также любые тест-хелперы модулей — деталь реализации, даже если формально импортируется.

    Карта импортов¶

    Top-level reactifact — удобный shortlist для core-примитивов и главных фасадов. Специализированные объекты живут в каноническом подмодуле; оттуда импортируйте, когда нужна полная поверхность:

    Что Канонический импорт
    шаги, группы, return-style инструкции, аннотации входов from reactifact.step import Step, StepGroup, Emit, Scope, Unscoped, Wakes
    consume-декларации и lifecycle-варианты from reactifact.consume import Consume, OnCreate, IdempotentConsume, JoinConsume
    chat-хуки и память from reactifact.chat import Chat, ChatAssistant, ChatReply, ChatMemory
    tool loops from reactifact.tools.use import ToolUse, NativeToolUse, ToolUseHITL
    агент/subflow как инструмент from reactifact.tools.agent import AgentAsTool
    провайдеры и их спецификации from reactifact.providers import LLMProvider, LLMSpec
    рецепты from reactifact.recipes import Route, ScopedCleanup, TurnContextStep
    верификация from reactifact.verify import Verify

    reactifact.__all__ остаётся shortlist’ом для Context, Artifact, Step, StepGroup, Consume, Effects, Runtime, Pipeline, Chat, Budget, lifecycle-consume’ов, CurrentRequest, аннотаций входов и инструментов. Freeze-тест фиксирует и top-level набор, и __all__ канонических подмодулей.

    Он-рамп (reactifact.quick)¶

    Тонкий сахар над примитивами ниже для четырёх частых первых задач — у каждого объекта есть настоящий .agent/.agents и .context запуска, поэтому он выпускается в Consume/Step/Effects без переписывания. См. Быстрый старт §0.

    Символ Роль
    agent(system, schema) один структурированный вызов LLM → один типизированный артефакт
    rag(sources) поиск → материализация → ответ, с провенансом supported_by
    tools_agent(system, tools, human=False) LLM + тулы (human=True → HITL-вопросы)
    chat_agent(groups) настроенный Chat (по умолчанию store в памяти)
    Question / Doc / Answer обобщённые модели артефактов, которые использует фасад

    Context и состояние¶

    Символ Роль
    Context версионируемое рабочее состояние; ресурсы; request (per-request mapping активного хода); запросы; latest(Model); announce; diff/checkout (at(version) для снапшота); compact(keep_commits=, keep_versions=) для ограничения истории (compacted_at); apply_commit(commit) проигрывает коммит в живое состояние (путь загрузки append-only сессии)
    View результат типа-запроса (context.view(...))
    RuntimeResources провайдеры + источники + ресурсы приложения; register(Type, instance, owned=False) / get(Type) / require(Type) / has(Type) для типизированных коллабораторов (ResourceKey[T], когда их два одного типа); явная регистрация выигрывает у артефакта того же типа; owned=True передаёт ресурс в aclose(); строковые get/set остаются escape hatch'ом (additional); redactor= вычищает текст трейсов; trace_truncate= ограничивает JSON артефактов/ответов в трейсе (None — без обрезки) — deprecated fallback (даёт DeprecationWarning), лучше TraceLimits(max_data_chars=…); await resources.aclose() закрывает owned-ресурсы (LIFO), затем HTTP-клиенты llm/embedder (duck-typed, async aclose() или sync close()) — вызывайте сами при завершении; record_tool_args=True пишет аргументы тулов в ToolRun (вычищаются redactor=)
    ResourceKey[T] типизированный ключ для регистрации двух ресурсов одного типа (primary/replica, per-tenant)
    ResourceScope / RuntimeResources.scope(factory) async with-билдер: создаёт ресурсы на текущем loop и закрывает на выходе — loop-safe способ владеть провайдерами
    current_request() request-маппинг активного хода (то же, что StepCall.request)
    CurrentRequest read-only Mapping из Runtime.arun(request=...); инжектируйте request: CurrentRequest (или используйте Step.request/call.request) вместо contextvar
    Commit, Read, Write учёт версий и записанные операции провенанса
    ContextCheckpoint лёгкое представление одного коммита (id, version, parent_ids, created_at, author, message, writes); context.checkpoints(), context.checkpoint(id/version), context.at(checkpoint)

    Артефакты и изменения¶

    Символ Роль
    Artifact неизменяемый handle (id, version, data, content_hash); история — в Context (artifact_version/version_history/find_versions)
    ArtifactConflict конфликт optimistic-concurrency: effects.update(..., expected_version=…) / Context.update ожидал другую версию; runtime проверяет всю generation до применения хоть одного patch
    register_type(Model, *, type_id=, aliases=, migrate=) (reactifact.types) стабильная персистентная идентичность типа: переименование/перенос модели больше не ломает загрузку старых сессий/коммитов/событий. type_id_of/resolve/migrate_payload; дефолтный id — qualified name
    Patch скомпилированный набор изменений рантайма (транспорт); шаги пишут эффекты (effects/call.effects), Patch собирает рантайм
    reactifact.operations (Create/Update/Delete/Link/Unlink/Relation) скомпилированные операции, которые несёт патч (§12)
    Create, Update, Delete, Link, Unlink, Relation записи операций, из которых строятся патчи

    Группы и шаги¶

    Символ Роль
    StepGroup опциональный тонкий контейнер: name, steps, concurrency_limit, retry, timeout, fallback; триггеры выводятся из consumes шагов. fallback=Step выполняется один раз после исчерпания retry, в свежем effects-слоте (effects неудачной попытки отбрасываются)
    create_step_group конструктор-фабрика StepGroup — без подкласса; принимает retry=/timeout=
    Runtime(steps=..., groups=...) диспетчеризует шаги и группы вместе (сначала шаги). Каждый голый Step оборачивается в неявную группу из одного.
    Chat(steps=..., seed_type=..., answer_type=...) типизированный чат-фасад: invoke/stream/history/answer, seed_factory, per_turn, resume_pending=, router(), http(), test_client(), traces=/lifespan=, store=. Pending PendingQuestion делает дефолтный ответ waiting: true со структурным question; resume_pending=True превращает следующий ход в ответ на него. .validate() / .describe() повторяют Pipeline; .http() — FastAPI-приложение с сессиями
    Pipeline(steps=..., groups=..., llm=..., traces=...) переиспользуемый фасад: .run(seed) / .arun(seed) сеют артефакт и возвращают RunResult; .answer(seed) / .aanswer(seed) возвращают типизированный answer_type; .astream(seed) отдаёт progress-события. Ресурсы/бюджет/tracer — дефолты конструктора; result.context / .last_context — escape hatches. .override(Type, instance) подменяет типизированный ресурс (тесты/фейки); lifespan= + async with управляют долгоживущими ресурсами; .test_client() добавляет in-memory trace store; traces=True|path пишет каждый запуск и заполняет RunResult.trace_id/.trace(). .validate() — статическая проверка контрактов; .describe() — ContractReport со схемами seed/answer; .router() / .http() — опциональные FastAPI-адаптеры; .as_tool() — представление как Tool/MCP-инструмент
    Daemon(pipeline, *, seed_source=, interval=, run_once=, max_ticks=) цикл по интервалу над Pipeline: seed_source(tick) может быть sync/async и вернуть None, чтобы пропустить тик; graceful SIGINT/SIGTERM, изоляция ошибок тика. Daemon(tick=fn) — форма для готовой tick-функции (шаблон daemon)
    RunResult .context, .runs, .outcome, .latest(Type), .sources(artifact), .hash, .trace_id, .trace()
    RetryPolicy политика повторов на агента: max_attempts, backoff, max_backoff, retry_on; повтор получает свежий Effects, поэтому коммитится только успешный patch
    run_subflow(parent, *, groups, input, output_type=, isolate=True, link=, source=, inherit_trace=True, inherit_budget=True, …) запускает дочерних агентов на изолированном Context (или ветке родителя), опционально линкует выходы к seed, прокидывает tracer и пишет trace_metadata.parent_run_id; возвращает SubflowResult
    SubflowResult context, seed, outputs, output, run_id, parent_run_id, stats
    describe_contracts(groups) / ContractReport статический контракт consumes/produces/tools (Markdown или JSON); CLI reactifact contracts <module> [--format md\|json]
    validate_contracts(*, steps=, groups=, seeds=, terminal=, budget=) / ValidationReport статическая проверка контрактов по шагам и/или группам (сначала шаги, как в Runtime): unknown inputs (errors), dead outputs/never-scheduled/unreachable/cycle/ambiguous_producer (warnings; последний подавляется для разных case одного Route); raise_for_errors(); CLI reactifact validate <module> (или graph --check)
    Wakes(False) / Scope / Unscoped / Consume / IdempotentConsume декларативная (или декоратор) завязка реакции; Consume.by_field для скоуп-событий; Consume.by_base / include_subclasses=True будит на наследниках marker-базы; IdempotentConsume(T, id_of=...) будит, только пока производного id нет; wakes=False — читать как вход, не будя агента (нужно только когда consumes выводится из подписи); debounce=True схлопывает несколько событий одного поколения в один запуск; Annotated[T, Unscoped()] читает T по всем ходам, а не только в scope шага (для истории комбинируйте с Wakes(False))
    OnCreate / OnUpdate / OnDelete / OnStale lifecycle-подклассы Consume: будить только на create/update/delete/stale; OnDelete требует event/Trigger, потому что данных уже нет
    reactifact.consume.CorrelatedConsume срабатывает (и питает входы) только для ключа корреляции, где присутствуют все типы из require и отсутствуют все из forbid — механизм за JoinConsume/AbsentConsume
    reactifact.consume.JoinConsume(*parts, key=…) фабрика над CorrelatedConsume: срабатывает, когда для одного ключа существуют все перечисленные типы
    reactifact.consume.AbsentConsume(type, absent_type=…, key=…) фабрика над CorrelatedConsume: срабатывает для type, только если для того же ключа ещё нет absent_type
    Step / @step единица работы (также scope= / Step(..., scope=...), produces=() + deletes=(T,) для side-effect-only шагов): класс run(...) получает типизированные входы + effects: Effects; функция @step получает типизированные входы (или legacy call: StepCall) и использует call.effects, когда нужен эффект-слот. consumes объявляет входы/триггеры, produces — разрешённые Create-типы; если consumes задан явно, типизированные артефактные параметры, которых там нет, добавляются как read-only входы (wakes=False); возврат модели — create-сахар. Annotated[T, When(...)]/Consume.by_* задают условия; дополнительные create — в том же tuple (produces=(Primary, Extra)). timeout= — жёсткий дедлайн шага; retry=, priority=, concurrency_limit= и name= копируются в неявную группу. Возвращайте Emit(model, id=..., links=(...)), когда id/провенанс должны быть явными, Ensure(...) — для идемпотентного create, Edit/Drop/Relate — для одиночной мутации
    Human / Outbox инжектируемые не-данные коллабораторы: human.ask/resume (HITL, PendingQuestion) и outbox.act (внешнее намерение, PendingAction); старые Effects.ask/resume/act удалены в 0.23
    Progress инжектируемый эфемерный progress-канал: progress(message, kind="status", **data) сразу публикует ProgressEvent (тонкая обёртка над Context.announce, никогда не коммитится). Шагу, который только объявляет статус и вызывает LLM/инструменты, Context не нужен; class-step может использовать self.progress(...)
    Emit / Ensure / Edit / Drop / Relate return-style инструкции изменений: create с явным id/links, идемпотентный create (по id или источнику), update полей, delete, link — компилируются в тот же атомарный патч. Emit с существующим id обновляет артефакт (upsert); Ensure пропускает, если он уже есть
    Trigger вторичное (не артефактное) условие входа шага; context_condition(artifact, context) — для условий, которым нужны другие артефакты (join/корреляция); флаг debounce, который читает Runtime
    StructuredGenerateAgent декларативный агент LLM→схема→артефакт (schema обязательна; build_prompt, fallback); хранит стабильный id результата на trigger
    LLMAgent блокирующий цикл LLM+инструменты (system, tools, max_steps, deferred_tool_groups); явный steps= мержится с внутренним tool-шагом
    HITLLMAgent цикл LLM+инструменты с паузами на ответ человека (max_asks, отчёт о возобновлении); явный steps= мержится с внутренним tool-шагом
    ToolUse, NativeToolUse, ToolUseHITL шаг цикла инструментов: mode="json" | "native" | "auto"; native использует run_tool_loop/provider tool calls + textual fallback, auto откатывается на JSON. ToolUse объявляет ToolAnswer; ToolUseHITL объявляет ToolAnswer/Observation/PendingQuestion и ждёт ответа человека. Подкласс может использовать self.progress(...) и возвращать Emit/Ensure (базовый возвращает Any)
    DeferredToolGroup (reactifact.tools.use) группа инструментов, чьи схемы не попадают в промпт, пока встроенный инструмент load_tools в ToolUse их не запросит (только LLMAgent/ToolUse, не HITL-вариант)
    Inject явный маркер Annotated[T, Inject()] для инжектируемого параметра тула (когда обычный класс неоднозначен); Depends — FastAPI-совместимый алиас
    Tool, FunctionTool, tool, ToolOutput, ToolError абстракция и регистрация инструментов; @tool(progress="Смотрю {service}") задаёт локализованный шаблон статуса для tool loop; Tool.execute инструментируется один раз (trace ToolRun + hooks + record/replay) и для прямых вызовов, и для execute_tool; @tool(retry=RetryPolicy(...), timeout=...) ретраит вызов; параметр с обычным классом инжектится из RuntimeResources (и не попадает в схему); pydantic-результат заполняет ToolOutput.data; ToolOutput.failed(ToolError(code=, message=, retryable=)) даёт типизированную ошибку, а ToolOutput.error остаётся обычной строкой
    ToolAnswer, Observation результаты инструментов и наблюдения модели (протокол цикла)
    PendingQuestion HITL-примитив: приостановленный вопрос, ждущий ответа человека, возобновляется через human.resume(...); опциональные resolution_schema, типизированный resolution_data, хелперы approved() / answer_text()
    Effects.update(artifact, *, expected_version=…, **fields) обновление полей существующего артефакта; expected_version= включает optimistic concurrency (ArtifactConflict вместо last-write-wins)
    PendingAction записанный внешний side effect (kind, idempotency_key, payload, status, attempts); выполняется один раз через Runtime(dispatcher=...), затем dispatched / failed (retry_action возвращает в очередь)

    Runtime¶

    Символ Роль
    Runtime будит агентов по событиям; run / arun / astream (каждый принимает request=Mapping); astream_events(stream_mode=...) отдаёт типизированные RunEvent; бюджет и параллельность; isolate_errors=True + on_agent_error(agent, event, exc), чтобы исключение одного агента не обрывало весь запуск (по умолчанию — пробрасывается, §69); dispatcher=async (context, action) дренирует outbox PendingAction после каждого коммита (один раз на стабильный id, удерживая ход живым, пока outbox не пуст); on_dispatch_error(action, exc) срабатывает, когда диспетчер падает (действие помечается failed, исключение пробрасывается); flush_pending_actions() дренирует без поколения (например, после merge()); Budget.max_seconds — жёсткий дедлайн хода (отменяет генерацию в полёте)

    Провайдеры (reactifact.providers)¶

    Каждый провайдер лениво создаёт httpx.AsyncClient и перепривязывает его к текущему event loop, поэтому один экземпляр провайдера переживает повторные asyncio.run(...) и per-test loop'ы (без RuntimeError: Event loop is closed); aclose() закрывает клиент текущего loop. То же — для WebSource и OTLP/Langfuse-приёмников.

    Символ Роль
    LLMProvider, EmbeddingProvider два контракта, с которыми говорит ядро; LLMProvider добавляет default-методы structured/structured_json/reply/chat (внутри вызывают complete, поэтому tracing/budget сохраняются), а EmbeddingProvider — embed_one
    ImageProvider, SpeechProvider, TranscriberProvider, VideoProvider медиа-контракты
    OpenAICompatProvider, OpenAICompatEmbedder + вендорные фабрики (openai_llm, anthropic_llm, deepseek_llm, groq_llm, mistral_llm, openrouter_llm, gemini_llm, ollama_llm, azure_llm, …) 20+ чат/эмбеддинг-бэкендов, у всех retry_attempts=3 по умолчанию (429/5xx/сетевые ошибки, экспоненциальный backoff — никогда на 4xx)
    openrouter_embedder, openrouter_speech, groq_transcriber, together_embedder, fireworks_embedder, qwen_embedder, nvidia_embedder эмбеддинги/TTS/STT для вендоров, чьи не-чат эндпоинты подтверждённо OpenAI-совместимы (см. providers)
    Message, Role одно сообщение чата; role — закрытый Literal + фабрики Message.system/user/assistant/tool
    LLMRequest одна генерация: messages + temperature/max_tokens — None = дефолт провайдера (вызов перекрывает провайдера, провайдер None = поле не отправляется)
